# V1 verification record

Date: 2026-11-06. Build 1.0.0, Debug, on a leased headless simulator and on GitHub's Macs.

## Commands

```bash
python3 scripts/verify.py
xcodebuild test -project Pet.xcodeproj -scheme Pet -destination "id=<leased UDID>" -parallel-testing-enabled NO
gh-sim all
```

## Results

- `verify.py` PASS: identity, production key format, products, both trials, metadata lengths, plist and source copy.
- Full suite after the Opus review fixes: 51 tests, 50 passed, 1 skipped (44 unit, 7 UI journeys). The skip is the StoreKit purchase test, which stalled on that simulator and passed on an earlier one. The journeys cover first-log onboarding, corrections, dose, invite paywall, sitter sheet, export, a simulated second caregiver, a stale medication notification that opens Now without logging, every main screen light and dark, large text, and the suggestion form with the network stubbed.
- GitHub's Macs: the purchase test stalls and the notification banner never shows, so both skip there. The notification test passes on a local simulator.
- Real bug found and fixed in testing: tapping any notification aborted the app (async delegate thunk off the main thread).

- CloudKit Production: schema deployed 2026-11-06. The Release `--verify-share` run made a real share there, resolved its link and removed the fixture, on one iCloud account.
- Suggestion loop: test #11 went from send to TestFlight build 4 in about an hour through the iMac session, with no help.

## Not proved yet (Gate 1)

- Two phones on two iCloud accounts: invitation acceptance, revocation, reinstall, import latency, long soak.
- Foregrounding producing an import inside the 5-minute staleness window, or Now reads "Stale" too often.
- Sandbox purchase through RevenueCat and customer attributes. The in-app purchase key shows valid and both subscriptions are READY_TO_SUBMIT, but no purchase has run on a phone.
