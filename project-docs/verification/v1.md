## Sign-in, unlock and background refresh (2026-11-16, build 12 code)

Proved in unit tests against real SQLite files on a leased simulator. Apple's transport, iOS's own timing and a real reboot are not covered.

- `testSignInAfterSignedOutLaunchMirrorsWithoutRelaunch`: a log opened signed out, with a meal logged, reopens with CloudKit mirroring on both stores on the next return to the app once an account appears. The meal stays, new entries save, the sync state turns on, and the same account does not reopen twice.
- `testLaunchBeforeFirstUnlockRecoversAfterUnlock`: with the data folder unreadable (as data protection leaves it before first unlock), the app runs on a stand-in and refuses writes. The unlock notification reopens the real files and shows the earlier entries without a relaunch.
- `testBackgroundRefreshCarriesRenewalToHouseholdRecord`: a StoreKit Testing purchase, then a forced renewal, run through `BackgroundRefresh.perform` alone. The household's "active until" moves to the renewed date, which keeps a joiner writable past the old date's 14-day grace.
- `testBackgroundRefreshIsPermittedByInfoPlist`: the task identifier is permitted and the `fetch` mode is on. BGTaskScheduler does not run on simulators.
- Build 13 on Jack's iPhone 17 Pro Max (iOS 27.2.1) through iPhone Mirroring, 2026-11-16: installed from TestFlight, onboarding (name, pet, species) completed, the Household paywall loaded live prices ($19.99 a year, $2.99 a month) and Get Started skipped the trial, a meal logged on Now with time and "Jack", Undo removed it, and Settings and Household opened. Not exercised there: sharing with a second account, sign-out, reboot.
